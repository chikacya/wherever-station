# 能力与边界

[English](CAPABILITIES.md)

## 产品定位

Wherever Station 是面向个人和小范围共享环境的聚合层，把服务器可观测性、节点资料、订阅分发和有限的托管实例管理放在同一界面。

它明确区分三类责任：

| 责任 | 权威数据来源 |
| --- | --- |
| 服务器身份、指标、登录、Agent 连接、远程任务传输 | Komari |
| 节点、订阅、来源、Provider 引用、流量计划、托管实例资料 | Wherever Station |
| 高级 sing-box 入站、客户端、路由和公网证书自动化 | S-UI、2S-UI 等专业面板 |

## 与 Komari 的关系

Wherever Station 是第三方 Komari 插件，使用 Komari 文档公开的插件能力：iframe 管理页、插件 RPC、公开路由、定时任务、系统 RPC 和 Agent 任务通道。它不 fork、不修改、不打包，也不替换 Komari。

Komari 继续负责：

- 管理员登录与插件授权；
- Agent 注册和在线状态；
- CPU、内存、磁盘、网络和历史指标采集；
- 把管理员明确提交的命令传输给 Agent；
- 插件生命周期和私有存储目录。

Wherever Station 在这些能力之上增加代理业务逻辑。没有 Komari 时插件不能独立运行；没有 Agent 时，节点导入和订阅分发仍可使用，但远程监控和操作不可用。

两个项目分别发布和授权。Komari 的 MIT License 不会改变 Wherever Station 的 GPL-3.0-only；Wherever Station 的 GPL 也不会把独立安装的 Komari 重新授权为 GPL。

| 能力 | 需要 Agent | 写目标主机 |

| 导入/编辑 URI 节点 | 否 | 否 |
| 拉取外部订阅 | 否 | 否 |
| 生成并提供订阅 | 否 | 否 |
| 读取 S-UI/2S-UI 分享链接 | 否 | 否 |
| 显示 Komari 服务器指标 | 是 | 否 |

## 状态和密钥

普通状态包含服务器资料、节点 URI、订阅 Token、订阅源 URL 和托管实例资料。S-UI/2S-UI API Token 保存在单独的服务端密钥文件中，使用严格文件权限，并从普通状态响应中剔除。

浏览器会话草稿使用 `sessionStorage`，Provider Token 不会进入草稿。二维码在浏览器本地生成。私钥内容不会返回浏览器，也不会保存进插件状态。

公开订阅路由有意不要求登录，以高熵订阅 Token 作为访问凭据。任何订阅 URL 都应按凭据保护。

## 远程操作模型

发现操作只读。修改操作只针对一台明确 Agent，并在管理员主动操作后提交。托管创建、编辑、生命周期、迁移、证书和删除操作使用请求标识与持久任务跟踪，避免页面重载后重复执行。

托管文件固定在 `/var/lib/proxy-console/`。已有服务名和已有配置路径不会成为托管写入目标。连接检查使用临时客户端，不会变成常驻测速服务。

## 监控口径

- 服务器速率和资源占用来自 Komari。
- 服务器流量计划使用 Agent 计数器，描述 VPS 套餐。
- 订阅额度来自指定订阅源、Provider 客户端或手动值。
- 进程运行不代表客户端一定能连接。
- Nowhere 协议遥测只展示明确实例且受支持接口的数据。
- 没有可靠逐节点数据源时，不宣称“每节点流量”。

## 明确不包含

Wherever Station 不提供：

- 通用 Shell 或终端；
- 任意 sing-box JSON 编辑；
- ACME/DNS Provider 自动签发；
- 公开注册、套餐、计费或代理商功能；
- 云安全组或防火墙自动修改；
- 未知已有代理配置的自动改写；
- 任意 URI 协议到任意结构化客户端格式的保证转换；
- 面向不可信租户的大规模集群编排。

这些边界让插件能够服务个人和小范围共享场景，而不重复实现第二套完整代理面板。
