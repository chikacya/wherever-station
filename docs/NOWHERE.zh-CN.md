# Nowhere 集成

[English](NOWHERE.md)

Wherever Station 无需依赖 `nowhere-sh` 即可管理 Nowhere。对于由插件创建的实例，它负责安装、配置、服务生命周期、遥测、证书和分享 URI。NW2 以 2.2.1 为存量基线，新建实例默认使用 NW3 3.0.0。

## 持续适配

Nowhere 的命令行、配置、传输或 URI 合同可能随版本变化。Wherever Station 会持续跟踪上游稳定版本，但可写操作仍以 [`tools/nowhere-compatibility.json`](../tools/nowhere-compatibility.json) 的显式适配器目录为准，不采用“版本更高就兼容”的推断。

| 状态 | 行为 |
| --- | --- |
| `verified` | 精确版本已进入回归矩阵，可执行受支持的生命周期与迁移操作。 |
| `compatible-range` | 能识别兼容系列，但精确版本尚未验证；保留识别能力，禁止写操作。 |
| `unknown-adapter` | 没有适配器；保留版本与实例记录，不生成命令或配置。 |

适配器目录是权威支持清单。NW1 不再适配，NW2 不再维护各个历史小版本的配置分支。旧 NW2 保留读取、启动、停止、重启、删除和升级至 2.2.1 的入口；不生成旧版本新配置。

## 版本发现与升级

版本选择器读取官方 GitHub Release，兼容状态来自本地适配器目录。新发现的 Release 在完成下载资产、校验和、CLI、配置、URI、生命周期、遥测、迁移与回退的隔离回归前保持只读。定时版本检查会报告尚未进入目录的稳定上游版本，及时启动适配工作，同时避免未经验证的写操作被静默开放。

存在官方 checksum 时，下载过程会进行校验。升级只作用于所选托管实例，并保留回退元数据。

托管实例会先读取目标机上的当前配置，再允许修改连接、Carrier、客户端输出、证书及高级运行参数。应用时使用配置指纹避免覆盖并发变化，失败会恢复旧配置。所属 VPS、实例身份、内核来源和接管来源不属于运行配置，分别由对应生命周期入口管理。创建和编辑共用同一套高级字段；尚未标准化的新版环境变量可在“实验性环境变量”中无损保留，但只应依照 Nowhere 官方文档使用。

## 证书与遥测

托管 Nowhere 实例可以引用上传的证书，也可以使用插件生成的自签证书。实例会显示证书归属、指纹、有效期和更新状态。公网可信的 ACME 证书建议由专门证书服务或面板签发后在此引用。

进程状态和流量遥测与 Komari 主机指标分别采集。从 Nowhere 2.0.2 开始，Wherever Station 会发现实例的受保护注册文件，并通过本地 Unix Socket 订阅 summary 快照；不会开放或占用 TCP 遥测端口。暂时缺少采样不代表宿主离线。

## 已有安装

发现过程采用保守策略：完整且受支持的定义可以导入；缺少凭据、公网地址或证书信息的结果会进入待修复草稿，不会猜测参数。

对可完整读取的 Nowhere 服务，可以选择**纳入管理**。纳管分成两个明确步骤：先复制当前内核与配置并创建一个停止状态的独立托管实例，原服务继续运行；用户核对后再执行切换接管。切换失败会尝试自动恢复原服务，接管成功后也可主动恢复原服务。原服务文件不会被覆盖或删除。未执行接管的服务始终位于 Wherever Station 生命周期边界之外。

## Nowhere 2.2.1 升级要求

Portal 和启用的原生下一跳共享密钥必须为 32–64 字符小写十六进制。新建实例会生成合规密钥；旧实例须先编辑配置，再同步所有客户端与下一跳。插件会在升级前拦截不合规密钥，不自动替换现有密钥。

原生 Vector、probe 和 next 默认校验系统 CA 与服务器名称；`sni=none` 或 `pin=none` 不会跳过校验。自签证书需使用实际叶证书 SHA256 指纹。托管连接检查先由所属 Agent 读取当前证书，2.2.1 使用官方 `fingerprint` 命令，支持 Morph；临时证书重启后须重新读取。仅 UDP 监听无法使用 TCP fingerprint，需要固定证书与已知指纹。Anywhere 分享 URI 支持 SNI，但不支持 pin，不能依靠该参数绕过客户端证书限制。

双栈出口可设置 `dial4` 和 `dial6`，填写对应地址族的本地 IP 或 `auto`；使用这些参数时插件省略 `dial`。已有单栈 `dial` 设置必须先恢复 `auto`。

现有合规的 32–64 字符密钥无需更换。过渡版本 2.2.0 不再作为安装或升级目标。

## NW3 3.0.0

NW3 与 NW2 不互通，没有协商或回退。确认客户端支持 NW3 后，可在“版本与证书”中选择 NW3，进入升级迁移预览；也可新建独立实例分阶段迁移。

所有角色的共享密钥必须为恰好 32 字符小写 hex，Morph 默认开启。NW2 的合规长密钥仍可留在 NW2，不能直接用于 NW3。

Portal 可监听 TCP/TLS 与 UDP/QUIC；每条 Vector 连接只选择一种 carrier。NW3 分享链接使用 `nowhere://KEY@HOST:PORT?net=tcp|udp&morph=0|1#NAME`，原生 Vector 使用 carrier path 和 `in=`。不再输出 split `up/down`、Mux 或原生 `next`。

高级配置中的 Portal 出口可填 `direct`、`egress` 或 SOCKS5 地址。`out=egress` 要求启用 QUIC listener，且不能指定出站源地址。Egress 使用主动 QUIC 连接，目标地址填远端 Portal，端口填其 QUIC 端口，密钥和 Morph 与 Portal 一致；自签 Portal 必须填写可信的 SHA256 Pin。Egress 不监听本地中继端口，也不生成订阅节点。Egress 断开后不会回退到 direct。

NW3 遥测只读 Hello 和周期 Snapshot，不发送订阅指令；保留进程实例 ID，以接收时间和累计字节差计算速率，重启后重新建立基线。仅显示逻辑 TCP/UDP 字节及活跃 Flow，CPU、RSS 等不属于 NW3 IPC 契约。进程状态来自 systemd。

第三方客户端的 NW3 支持须单独核实。相同 `nowhere://` scheme 不表示旧客户端可以连接 NW3。

## 批量更新

部署节点页面提供“批量更新 Nowhere”。预览会列出所有已部署的托管实例及其同代际目标：NW2 使用 2.2.1，NW3 使用目录内最新已验证版本。草稿、已是目标版本、当前版本更高、未绑定 Agent、待接管或已有任务的实例会跳过；密钥及配置检查不通过时不会自动修改凭据或跨代升级。

开始后界面显示已处理实例数、整体进度及每项结果。提交阶段需保持页面打开；提交完成后的下载和更新由 Agent 执行，关闭窗口、切换页面或刷新后可继续查看同一批次。失败任务单独报告，已停止服务保持停止，更新失败按原有升级事务回退。无法确认提交或远端结果时标为“待核对”，不自动重复执行。记录保存 24 小时。

范围仅包含插件已管理或已接管的实例；没有纳入管理的独立 nowhere.service 不会批量替换。批量更新不会把 NW2 升到 NW3。

## NW2 → NW3 升级迁移

在“版本与证书”选择已验证的 NW3，点击“迁移到 NW3”。插件先从目标机读取配置并保存指纹，再预览转换。32 字符小写 hex 密钥可保留；更长或不合规密钥需在迁移表单中明确更换，不截断旧密钥。Mux、分离 up/down、旧遥测设置会移除，SOCKS 转换为 `out=`，监听端口、限速、证书和 Morph 开关保留。原生 `next` 不能自动转换，必须先调整链路。

确认所有客户端支持 NW3、准备同步密钥和 Morph 后才可执行。远端配置若已变化会在停服前拒绝迁移。迁移失败恢复旧二进制、配置和原有运行状态；原先停止的实例会短暂启动验证新配置后恢复停止。成功后才发布 NW3 订阅链接，保留私有 `.nw2-backup` 二进制和配置用于恢复。NW2 管理入口继续保留；后续待 NW3 新版本或存量全部迁移后再决定清理，不自动删除。
