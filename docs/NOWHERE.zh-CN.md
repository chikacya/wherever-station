# Nowhere 集成

[English](NOWHERE.md)

Wherever Station 无需依赖 `nowhere-sh` 即可管理 Nowhere。对于由插件创建的实例，它负责安装、配置、服务生命周期、遥测、证书和分享 URI。目前仅支持 NW3，新建实例默认使用稳定版 3.1.0。NW2 的适配、新建、管理和迁移入口已移除；历史记录与备份不自动删除。

## 持续适配

Nowhere 的命令行、配置、传输或 URI 合同可能随版本变化。Wherever Station 会持续跟踪上游稳定版本，但可写操作仍以 [`tools/nowhere-compatibility.json`](../tools/nowhere-compatibility.json) 的显式适配器目录为准，不采用“版本更高就兼容”的推断。

| 状态 | 行为 |
| --- | --- |
| `verified` | 精确版本已进入回归矩阵，可执行受支持的生命周期和同代际更新操作。 |
| `compatible-range` | 能识别兼容系列，但精确版本尚未验证；保留识别能力，禁止写操作。 |
| `unknown-adapter` | 没有适配器；保留版本与实例记录，不生成命令或配置。 |

适配器目录是权威支持清单。NW1、NW2 均不再支持。旧版本记录只保留展示，不生成配置或远程操作命令。

## 版本发现与升级

版本选择器读取官方 GitHub Release，兼容状态来自本地适配器目录。新发现的 Release 在完成下载资产、校验和、CLI、配置、URI、生命周期、遥测、迁移与回退的隔离回归前保持只读。定时版本检查会报告尚未进入目录的稳定上游版本，及时启动适配工作，同时避免未经验证的写操作被静默开放。

存在官方 checksum 时，下载过程会进行校验。升级只作用于所选托管实例，并保留回退元数据。

托管实例会先读取目标机上的当前配置，再允许修改连接、Carrier、客户端输出、证书及高级运行参数。应用时使用配置指纹避免覆盖并发变化，失败会恢复旧配置。所属 VPS、实例身份、内核来源和接管来源不属于运行配置，分别由对应生命周期入口管理。创建和编辑共用同一套高级字段；尚未标准化的新版环境变量可在“实验性环境变量”中无损保留，但只应依照 Nowhere 官方文档使用。

## 证书与遥测

托管 Nowhere 实例可以引用上传的证书，也可以使用插件生成的自签证书。实例会显示证书归属、指纹、有效期和更新状态。公网可信的 ACME 证书建议由专门证书服务或面板签发后在此引用。

进程状态和流量遥测与 Komari 主机指标分别采集。从 Nowhere 2.0.2 开始，Wherever Station 会发现实例的受保护注册文件，并通过本地 Unix Socket 订阅 summary 快照；不会开放或占用 TCP 遥测端口。暂时缺少采样不代表宿主离线。

## 已有安装

发现过程采用保守策略：完整且受支持的定义可以导入；缺少凭据、公网地址或证书信息的结果会进入待修复草稿，不会猜测参数。

对可完整读取的 Nowhere 服务，可以选择**纳入管理**。纳管分成两个明确步骤：先复制当前内核与配置并创建一个停止状态的独立托管实例，原服务继续运行；用户核对后再执行切换接管。切换失败会尝试自动恢复原服务，接管成功后也可主动恢复原服务。原服务文件不会被覆盖或删除。未执行接管的服务始终位于 Wherever Station 生命周期边界之外。

## 证书与连接校验

NW3 共享密钥必须为恰好 32 字符小写十六进制。Vector 与连接检查默认验证证书，自签证书需使用实际叶证书 SHA256 指纹。插件使用本实例的官方 `fingerprint` 命令读取指纹，支持 Morph；临时证书重启后须重新读取。仅 UDP 监听需固定证书与已知指纹。

双栈出口可设置 `dial4` 和 `dial6`，填写对应地址族的本地 IP 或 `auto`；使用这些参数时插件省略 `dial`。已有单栈 `dial` 设置须先恢复 `auto`。

## NW3 3.0.0

只管理 NW3 实例，旧 NW2 不能通过本插件新建、接管、升级或迁移。需要继续使用的历史服务由用户独立处理，插件不会更改或删除它。

所有角色的共享密钥必须为恰好 32 字符小写 hex，Morph 默认开启。长密钥不能直接用于 NW3。

Portal 可监听 TCP/TLS 与 UDP/QUIC；每条 Vector 连接只选择一种 carrier。NW3 分享链接使用 `nowhere://KEY@HOST:PORT?net=tcp|udp&morph=0|1#NAME`，原生 Vector 使用 carrier path 和 `in=`。不再输出 split `up/down`、Mux 或原生 `next`。

高级配置中的 Portal 出口可填 `direct`、`egress` 或 SOCKS5 地址。`out=egress` 要求启用 QUIC listener，且不能指定出站源地址。Egress 使用主动 QUIC 连接，目标地址填远端 Portal，端口填其 QUIC 端口，密钥和 Morph 与 Portal 一致；自签 Portal 必须填写可信的 SHA256 Pin。Egress 不监听本地中继端口，也不生成订阅节点。Egress 断开后不会回退到 direct。

NW3 遥测只读 Hello 和周期 Snapshot，不发送订阅指令；保留进程实例 ID，以接收时间和累计字节差计算速率，重启后重新建立基线。仅显示逻辑 TCP/UDP 字节及活跃 Flow，CPU、RSS 等不属于 NW3 IPC 契约。进程状态来自 systemd。

第三方客户端的 NW3 支持须单独核实。相同 `nowhere://` scheme 不表示旧客户端可以连接 NW3。

## 批量更新

部署节点页面提供“批量更新 Nowhere”。目标选择器仅提供最新两个已适配的 NW3 版本，包含预发布版并明确标识；默认选择稳定版，预发布需手动选择。选择或切换版本后重新生成实例清单，并重置客户端兼容确认。草稿、已是目标版本、当前版本更高、未绑定 Agent、待接管或已有任务的实例会跳过；密钥及配置检查不通过时不会自动修改凭据或跨代升级。

开始后界面显示已处理实例数、整体进度及每项结果。提交阶段需保持页面打开；提交完成后的下载和更新由 Agent 执行，关闭窗口、切换页面或刷新后可继续查看同一批次。失败任务单独报告，已停止服务保持停止，更新失败按原有升级事务回退。无法确认提交或远端结果时标为“待核对”，不自动重复执行。记录保存 24 小时。

范围仅包含插件已管理或已接管的实例；没有纳入管理的独立 nowhere.service 不会批量替换。批量更新不会把 NW2 升到 NW3。

## 3.2.0 升级边界

3.0.1 新增默认 `fade` Prelude；3.1.0 开始发送认证 Prelude 并兼容旧客户端；3.2.0 Portal 对 Morph TCP 强制验证认证 Prelude。NW3 Core、URL、共享密钥与遥测不变，但“同 NW3”不再足以判定客户端兼容。

升级至 3.2.0 前先更新全部 Morph TCP 客户端：原生 Vector 至少 3.1.0，第三方客户端需明确实现认证 Prelude。单实例升级需确认；批量更新未确认时跳过相应实例。QUIC、未启用 Morph 的 TCP、仅作为主动 QUIC 出口的 Egress 不受这一 TCP 边界影响。远端脚本也会在停服前核对实际 URL，避免管理记录过期时绕过检查。

高级表单可选 `fade/full8/low7`，仅影响本端生成的 Prelude 分布，不代表认证能力，也无需两端使用相同分布。3.0.0 默认仍为 full8；升级保留已有显式设置。3.2.0 移除的 `NOW_UDP_DATA_BUF_SIZE` 会从配置清除。连接测试遇到旧原生客户端会提示升级检测客户端，不误报为服务器连接失败。

官方依据：[3.0.1](https://github.com/NodePassProject/Nowhere/releases/tag/v3.0.1)、[3.1.0](https://github.com/NodePassProject/Nowhere/releases/tag/v3.1.0)、[3.2.0](https://github.com/NodePassProject/Nowhere/releases/tag/v3.2.0)。

发布状态核验（2026-10-28）：上游 v3.2.0 标记为 prerelease，稳定版为 v3.1.0。因此默认安装和批量更新的默认目标为 v3.1.0；v3.2.0 保留已验证的手动适配和安全检查，不进入自动目标。


## 预发布版本

官方列表保留 NW3 预发布版，在版本后标注“预发布”；已适配并验证的版本可在新建实例和“版本与证书”中手动选择。GitHub 不可用时，已验证的 3.2.0 也保留在缓存列表。默认仍使用 3.1.0；批量更新可手动选择最新两个已适配版本中的预发布版，不会自动升级到预发布，也不会因有更低稳定版而默认降级已运行的更高版本。未适配版本（含带 rc/beta 后缀的版本）列出状态但不能执行升级，需完成对应适配后开放。

2026-10-29 核验：3.2.0 仍为官方预发布，3.1.0 为稳定版；3.2.0 的 Morph TCP 认证 Prelude 边界和停服前检查继续生效。NW2 支持现已移除，不再提供旧版本基线或迁移入口。

批次提交后目标版本写入持久化记录，刷新页面或返回进度时保持不变；运行中不能更改目标。已是目标版本或版本更高的实例跳过，不批量降级。后端同时验证目标是否属于最新两个版本，不仅限制下拉框。
